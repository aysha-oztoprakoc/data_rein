## Claim reconciliation

### Supported by the repository

- The harness has a single Wiki SQLite database and an idempotent
  `reins wiki consolidate` path.
- Task Trail state is persisted in SQLite under
  `~/.config/data_nexus/task_trail.sqlite3`.
- Model routing and explicit cloud escalation are represented in the harness;
  local-first routing is the intended default.
- `src/reins/harness/coordinator.py` implements VRAM admission, fallback, and
  LRU-style eviction logic.
- The canonical `skills/` tree is linked into the supported agent environments
  by `reins skills install`.
- MCP, extraction, training, and remote-to-local inference components named by
  the explanation exist in the source tree.

### Supported only with qualification

- “Zero polling” is a design law and a static-check target, not proof that every
  process has 0.00% CPU. The bundled PON checker is regex-based and was run on
  the harness target successfully; that result is useful evidence, not a formal
  whole-system proof.
- The amdy/tell split means durable state ownership, not literal absence of all
  local memory. Coordinators necessarily use transient admission/cache state;
  the canonical PON skill now states this explicitly.
- Hardware values are claims in the hardware manifest and should be treated as
  point-in-time inventory, not immutable runtime facts. Capacity decisions must
  use the live coordinator/configuration path.
- Nix and uv provide reproducible environment mechanisms, but the explanation
  does not establish that every external runtime, model artifact, or generated
  PDF is bit-for-bit reproducible.
- The repository contains LoRA/QLoRA-related code, but the paper must not infer
  that a completed training benchmark or a production-grade QLoRA pipeline
  exists without a recorded run and metrics.

### Corrected project inconsistencies

- The canonical manifest already had eight rows, including `deep-research-paper`,
  while its prose still said “seven.” The prose now says eight.
- `pon_testing_suite/SKILL.md` was the only canonical skill missing the `tags`
  frontmatter promised by the manifest. Its metadata now includes tags.
- `tests/test_skill_installer.py` used a seven-skill synthetic fixture and did
  not cover `deep-research-paper`; the fixture now covers all eight names.
- The PON skill’s statement that execution nodes hold “no local state” was too
  absolute for the coordinator implementation. It now distinguishes durable
  state from transient local admission/cache state.

## Paper sanity verdict

The two available PDFs are coherent as technical drafts, but they are not
submission-ready evidence of an “exhaustive” implementation. The prior audit
found unsupported absolute claims about PON compliance, hardware saturation,
token efficiency, and empirical results, plus source/reference and
implementation mismatches. Those findings are preserved in the linked report.

The correct next input for a v5 audit is the actual v5 PDF or source package.
Until it is present, the project is updated and the available paper is checked,
but v5-specific claims cannot be verified.
