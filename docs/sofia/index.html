Sofia³ Web Dashboard & Task Trail

The Sofia³ dashboard has been engineered as a zero-polling reactive command center. Leveraging an Omarchy Cyberpunk design system, it provides a panoramic view of the cluster without incurring polling loops or CPU overhead.

Redux Telemetry Widgets

  • HardwareWidget: Tracks GPU, VRAM, RAM, and CPU specs, rendering model admission capabilities in real time.
  • OmniRouterWidget: Visualizes token budget utilization and provider combo tiers (via Recharts).
  • PonHealthWidget: Validates the 0% idle CPU state, watching the inotify SQLite WAL and MQTT bus connection.
  • CoordWidget: Reports the resident model slot, allocated VRAM, and dynamic agent budgets.
  • TasksWidget: A live stream of autonomous events powered by the Tiered Task Trail API.

Tiered Task Trail API

The universal task trail has been refactored to protect LLM context windows and reduce websocket payload bloat.

  • Summary View API: The websocket bridge serves a lightweight payload (`task_id`, `status`, `title`) to ensure high-performance streaming across nodes.
  • Lazy Loaded Details: The full JSON payload of a task's execution graph is fetched asynchronously via REST only upon user interaction.
  • Parent/Child Folding: Micro-tasks and remote compilation steps are folded into their parent process, hiding execution noise from the main timeline.
  • Soft-Archiving: Long-running continuous agents will smoothly archive old tasks, performing garbage collection to prevent UI freezing.

LiveBridge WebSocket Architecture

Sofia³’s LiveBridge strictly adheres to the Notification-Oriented Paradigm (PON):

The backend subscribes to the data_rein/trail/task/# MQTT channels and an inotify watcher on the SQLite WAL. State changes instantly wake an `asyncio` worker that fans out the latest state vector to all connected clients. No while True: sleep(1) polling loops exist anywhere in the pipeline.
