The 10 Laws (TEN_LAWS)

Notification-Oriented Paradigm (PON)

All code written under this harness obeys the Notification-Oriented Paradigm. Zero polling is permitted. Execution nodes wait via blocking I/O, reactive pipes, or MQTT subscription, ensuring idle CPU cost remains near zero.

  • PON-1: No active status polling (`while True`, `time.sleep()`).
  • PON-2: Strict role separation between `amdy` (Methods) and `tell` (State).
  • PON-3: FBE abstraction. Entities do not chain-call; they change Attributes which fire notifications.

Graceful Degradation

The system must degrade under failure, never crash entirely. Circuit breakers and failover routes are strictly enforced.

  • GD-1: All execution frames are wrapped in immortal circuit breakers.
  • GD-2: Fallback to a lesser model or node automatically on timeout.
  • GD-3: Log all failures to the Universal Task Trail for visibility.
